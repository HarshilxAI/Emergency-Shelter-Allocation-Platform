7. FIND EMERGENCY SHELTER — IMPORTANT FUNCTIONAL CHANGE
================================================================

This section requires a SIGNIFICANT functional improvement.

Current problem:

The system effectively assumes that the emergency location is the
current user's location.

That is WRONG for our use case.

A logged-in user may be creating an emergency request for another
person who is NOT physically with them.

Example:

User is in Bengaluru.
Their relative/friend is somewhere else.
User creates a shelter request for that person.

The system MUST use the affected person's/request location,
NOT automatically use the logged-in user's current location.

------------------------------------------------
LOCATION MODE
------------------------------------------------

The "Where are you?" section must provide two explicit options:

1. Use my current location
2. Enter location manually

These must be clearly distinguishable.

Example UI:

[ Use my current location ] [ Enter location manually ]

OR an equivalent clean segmented control.

------------------------------------------------
CURRENT LOCATION MODE
------------------------------------------------

If the user chooses:

"Use my current location"

then:

- Request browser geolocation permission
- Obtain the user's current coordinates
- Show the location on the map
- Use those coordinates for this emergency request
- Store those request coordinates in the request payload

Do NOT treat them as permanent user profile location.

------------------------------------------------
MANUAL LOCATION MODE
------------------------------------------------

If the user chooses:

"Enter location manually"

then DO NOT request/use the logged-in user's current location.

Instead allow the user to enter the affected person's location.

Provide:

- Address / area / landmark search field
- Map interaction if supported
- Location marker
- Confirmed location state

Example:

"Search address, area or landmark"

The user should be able to enter something such as:

"Koramangala 4th Block, Bengaluru"

or another location.

The request must use the manually selected location.

The logged-in user's geolocation must NOT overwrite it.

------------------------------------------------
CRITICAL BACKEND REQUIREMENT
------------------------------------------------

The selected request location must actually flow through the backend.

Do NOT implement manual location only as a frontend visual.

Inspect the existing request API/schema.

Ensure the request contains the selected location coordinates/address.

The shelter ranking engine must use:

REQUEST LOCATION

not:

LOGGED-IN USER LOCATION

for:

- distance calculation
- shelter ranking
- nearest shelter
- route generation
- recommendation results

The request location should be treated as independent from the
logged-in user's location.

------------------------------------------------
LOCATION STATE
------------------------------------------------

Clearly show:

Location selected

and whether it came from:

- Current location
OR
- Manual location

Do not expose unnecessary personal location information.
